# 换行规范 v1

此规范定义本项目的中英文混排策略，不宣称完整实现 Unicode UAX #14 或专业出版排版标准。规则文件为 `linebreak-rules.json`，版本由 `schema_version: 1` 固定。未知字段、空术语、非有限数值及越界比例会明确报错。

## 决策顺序

1. 先解析有限的 Markdown 行内格式：`**加粗**` 与 `[文字](https://example.com)`。普通 HTML 按文字显示；链接只接受 HTTP(S)。格式边界不会产生额外断点，`**Type**Script` 仍是一个完整单词。
2. 将可见文字转换为原子单元：配置术语优先且最长匹配，其次是数字及单位、URL、英文技术词、空白和单个中文字符。中文扩展字符同样以字符为单位处理。表情及组合字素不在本版保证范围内。
3. 以实际字号和字体逐段测量宽度；加粗按粗体字体测量。可用宽度扣除 `width_safety_pt`，默认保留 0.25 pt。
4. 贪心选择能容纳的最长前缀，再回退到合法标点边界。自动产生的新行不得以闭标点开头，上一行不得以开标点结尾；判断时忽略边界空白。原文自己开头或结尾的不配对标点不自动改写。
5. 若最后一行过短，只重排最后两行。末行目标为 `min(可用宽度 × last_line_min_ratio, 字号 × last_line_min_chars)`，默认比例 0.25、字数当量 12。前一行至少保留可用宽度的 0.6；找不到同时满足标点、宽度和长度的断点时保留原结果。长度为软目标。
6. 显式插入 `<br/>` 后交给 ReportLab。渲染器实际行数必须与测量结果相同，否则报错；不接受渲染器静默再次拆行。

## 原子单元

| 内容 | 规则 |
| --- | --- |
| `Python`、`TypeScript`、`Node.js`、`CI/CD`、`C++` | 整个技术词保持在同一行；英文句子可以在词间换行 |
| `12.5 ms`、`10 万条`、`25%` | 数字、可选空格及配置中的单位保持在同一行 |
| `2024.03 - 2025.09` | 数字范围保持在同一行 |
| `Docker 镜像` | 通过 `keep_together` 显式保护，内部空格保留 |
| 普通中文 | 逐字提供断点，受标点禁则约束；不会自动识别所有中文词语 |
| 链接 | 以显示文字测量；显示文字可换行，每段保留同一个目标 URL |
| 裸 URL | 保持原子性；过长时建议使用短链接文字 |

数字单位区分大小写。新增专有词应修改规则文件，无需修改 Python。配置术语跨加粗或链接边界仍然匹配。标点集合可以调整，默认值见 JSON。

## 空白和段落

保留段内空格，包括加粗文字之后的空格；去除每个显示行两端的空白。不得为视觉效果增加、删除或替换正文文字。换行时落在边界的空白会移除，末两行重新分配时使用原始单元恢复词间空白。

Markdown 输入是面向简历的明确子集：姓名、职位、联系方式分别占一行；`##` 表示章节，`###` 表示条目，`- ` 表示列表项。每个未缩进的内容行形成一个段落；空行用于源码可读性，不产生额外垂直间距。以至少两个空格或制表符缩进的续行，合并到前一内容行，连接处补一个空格。它与通用 Markdown 的软换行行为有区别。

模块接口接受的 `\n` 是显式换行，末行调整不会跨越它。JSON 术语不允许换行。本版不支持嵌套列表、表格、图片、斜体和任意 HTML。

## 超限行为

任何不可拆单元或标点组超过栏宽时，立即报错并提示缩短内容、增大栏宽、使用短链接文字或修改术语保护。不会悄悄截断或拆坏英文词。

PDF 只生成 A4 单页。正文按固定档位从 9.2 pt 尝试到 8.2 pt；所有档位都无法容纳时，要求精简原文。正文不会无限缩小，失败时不会替换已有输出 PDF。

字体变化会影响换行位置。要获得一致结果，使用相同的 ReportLab 版本、字体文件、规则文件及 Markdown 输入。
